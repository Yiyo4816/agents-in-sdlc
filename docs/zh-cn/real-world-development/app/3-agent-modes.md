我们先为项目添加了一个小功能，但更大的更改需要更完善的流程。幸运的是，GitHub Copilot app 能够配合组织现有的工作流程，帮助我们以正确的方式构建正确的功能。这是多节课程中的第一节，你将体验典型的智能体驱动开发流程：从使用议题生成新功能开始，确保代码有效、功能符合预期，最终成功将更改合并到项目中。

> [!NOTE]
> 在后续功能开发流程中，你将继续使用同一个会话。通常，你会为要处理的不同文件类型分别创建会话或 PR；本研讨会会采用快捷方式，帮助你专注于核心概念。

本课将学习如何：

- 从 GitHub 议题启动新的智能体会话。
- 在 **Plan** 模式中确定需求。
- 使用 **Autopilot** 模式实现新功能。
- 审查代码。
- 在浏览器画布中手动验证功能。

在继续开发此功能的过程中，你将更新存储库说明、自定义现有的质量检查技能、添加 MCP 验证、创建 QA 智能体，并打开功能 PR。

## 场景

Tailspin Toys 的游戏目录不断扩大，访客需要按类别和发行商筛选游戏。待办事项中的议题描述了该功能，但组合类别等细节需要在编码前达成共识。你将使用 Plan 模式明确这些决定，然后授权 Autopilot 在限定范围内完成实现。

## 背景

在开发流程中引入 AI 编码智能体并不会改变基本原则。事实上，这些原则会变得更加重要！大多数开发者的流程大致如下：

1. 打开一项已创建的议题，了解需要完成的工作。
2. 制定要构建内容的计划。
3. 编写并审查代码。
4. 运行测试以验证代码。
5. 手动验证新功能。
6. 创建拉取请求（PR）。
7. 代码通过审查且持续集成流程成功后，合并代码。

> [!NOTE]
> 根据团队和组织的不同，具体细节会有所变化，但大多数流程都与上述方式类似。

遵循这种标准方法，可以确保 AI 生成的代码符合需求，并经过与手工编写的代码相同的审核流程。

## 会话模式

**会话模式**控制智能体的自主程度。你可以从提示字段下方的下拉菜单中设置模式，也可以随时更改：

- **Interactive**：你与智能体协作。智能体提出更改建议，并等待你输入后再继续。
- **Plan**：智能体先制定计划。你审查并批准计划后，智能体才会执行。
- **Autopilot**：智能体完全自主地工作——编写代码、运行测试并迭代，无需等待你的输入。

先从 Plan 模式开始，审查计划，然后使用 Autopilot 实现计划。

## 从议题启动会话

开始前，确认星级评分 PR 已经合并，并且本地 `main` 分支已更新到最新状态。

1. 在侧边栏的 **Sessions** 下，选择 Tailspin Toys 存储库文件夹，然后在存储库顶部导航中选择 **Issues**。打开 **Allow users to filter games by category and publisher**。这是一个预先创建的议题，无需再创建一项。
2. 选择 **New session**，并选择基于已更新 `main` 创建的**新工作树**。

    ![GitHub Copilot app 中的议题视图，箭头指向 New session 按钮](../../../_images/app-new-session-from-issue.png)

3. 确认该议题已关联到会话，然后从模式选择器中选择 **Plan**。

> [!NOTE]
> 如果找不到 Node.js 或 npm，请让智能体运行 `node --version` 和 `npm --version`。如果它们在终端中可用，但在会话中不可用，请检查应用的 PATH 或版本管理器设置，然后完全退出并重新打开应用。重试失败的操作和检查；不要仅仅因为智能体找不到 npm 就重新安装 npm。

## 规划筛选功能

制定计划可以让你在 Copilot 编写代码前审查实现方法。由于你从议题启动会话，Copilot 已经获得了功能请求作为上下文。发送：

```plaintext
Build this feature.
```

回答 Copilot 的问题，并将计划与议题的验收标准进行比较。确认计划涵盖类别和发行商筛选、可访问的控件、数据访问更改和测试。讨论任何不明确的行为，例如多个类别如何组合，或者没有游戏匹配时会发生什么。

计划应包括使用项目现有工具运行 lint、单元测试、E2E 测试和类型检查。让计划专注于实现和测试筛选功能；完成质量工作流程后再创建 PR。批准前，要求修改计划中需要调整的部分，并记下议题 URL 以及已商定的说明，供稍后验证时使用。

## 明确批准 Autopilot

对计划满意后，选择 **Approve and implement this plan**，或当前版本中含义相同的选项。不要假设批准计划会自动切换模式；请确认模式指示器显示 **Autopilot**。

Copilot 随即开始实现！你会看到它按照既定计划迭代、生成代码并运行测试。

> [!NOTE]
> 批准计划后，实现可能立即开始，因此请先审查计划。如果 Copilot 报告缺少依赖项或端口冲突，请先解决设置问题，再将检查视为已完成。只停止由你启动的服务器。

## 审查并验证实现

代码生成后，和其他代码一样，在合并前需要审查。我们一起来审查代码并运行网站，确认一切正常。

1. 打开 **Changes**，检查筛选功能的实现和测试。
2. 将结果与议题及已批准的说明进行比较，包括类别和发行商的组合情况。检查更改是否遵循现有存储库说明。
3. 查看 lint、单元测试、E2E 测试和类型检查的输出。跳过的检查不算通过。
4. 解决失败项并重新运行受影响的检查，然后再接受实现。Playwright 的 E2E 配置会构建并运行预览，也可能复用本地服务器；请确认被测服务器属于此工作树，而不是上一课留下的服务器。

## 探索新功能

代码看起来没问题，但它能运行吗？像前一课一样启动应用，并在浏览器画布中打开网站。

1. 使用以下提示，请求 Copilot 启动应用并在浏览器画布中打开页面：

    ```plaintext
    Start the app and open it in the browser canvas.
    ```

2. 片刻之后，应用会启动，GitHub Copilot app 中也会打开一个浏览器窗口。
3. 选择一个类别，确认结果与该类别匹配。清除筛选器，然后选择一个发行商，确认结果与该发行商匹配。
4. 同时使用类别和发行商筛选器，并将结果与议题及已批准的计划进行比较。如果支持多个类别，请验证已商定的组合行为。
5. 尝试一种没有匹配游戏的筛选组合，并检查空状态。清除或重置筛选器，确认完整列表重新显示。
6. 完成后，使用以下提示要求 Copilot 停止它为此会话启动的开发服务器：

    ```plaintext
    Stop the dev server and close the browser canvas.
    ```

## 为后续课程保留此会话

现在不要创建或合并筛选功能 PR。请保留此会话、工作树和分支，供第 4 至第 8 课继续使用。接下来，你将为筛选代码应用自定义说明，然后添加技能和 QA 改进，最后在第 8 课创建并合并综合 PR。停止开发服务器后，可以让会话保持空闲；下一课再返回此会话。

- 使用 **Autopilot** 模式实现新功能。
