Copilot を agent mode で使うと、コードベースを調べ、変更を提案し、ファイルを編集して、コマンドを実行します。VS Code の Copilot Chat では、作業がローカルでリアルタイムに進むため、ツールの呼び出しやファイルの編集を逐一確認できます。差分をインラインでレビューし、個別の変更を承認または取り消し、エディターを離れずに追加のプロンプトを送って作業を調整したり広げたりできます。

この演習では、次の操作を行います。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集を確認して、適用するか判断します。
- セッションの途中でエージェントに指示を出し、ハイコントラストモードに加えてライトモードも追加します。

## シナリオ

[演習 4][previous-lesson] で使ったアクセシビリティ用カスタムエージェントは、ハイコントラストモードを実装しています。作業中、デザインチームから追加の要望がありました。既定のテーマが暗すぎると感じる利用者向けに、ライトモードも切り替えられるようにします。新しい会話を始める代わりに、進行中のセッションに指示を出して作業を拡張します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが行う各手順が表示されます。調査したファイル、実行したコマンド、提案した編集を確認できます。ファイル編集は差分と **Keep** / **Undo** コントロールとともにチャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、ツールの呼び出しを確認します。ファイルの読み取りや編集、エージェントが求めたターミナルコマンドが表示されます。
3. エージェントがファイルの編集を提案すると、差分がチャット内に表示されます。
   - **Keep** を選択すると変更を適用します。
   - **Undo** を選択すると変更を取り消し、エージェントにやり直してもらいます。
4. チャット上部の **Files changed** を開くと、セッション中にエージェントが変更したすべてのファイルを確認できます。

> [!NOTE]
> ターミナルコマンドの実行などで許可が必要な場合、エージェントは一時停止し **Allow** を表示します。実行してよいコマンドだけを許可してください。

5. エージェントがハイコントラストモードの実装を終えるまで待ちます。最後に、変更内容の概要が表示されます。

## ライトモードを追加するようエージェントに指示する

ハイコントラストモードが実装されたら、同じ会話でライトモードの切り替えも追加します。会話を続けることで、エージェントは前の作業（変更したコンポーネント、使ったスタイル、設定した local storage の方法）を引き続き参照できます。

1. Copilot Chat の入力欄に、次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントが既存の変更を調べ、ライトモードの追加を提案します。
3. ハイコントラストモードのときと同じように、新しい編集を確認し、それぞれ **Keep** または **Undo** を選びます。
4. エージェントの進め方が希望と異なる場合（例: 切り替え UI を意図しない方法でリファクタリングする場合）は、入力欄の横にある **Stop** ボタンで中断し、追加の説明を送ります。

> [!TIP]
> 進行中のセッションに指示を出すと、最初からやり直すより早く調整できます。追加のプロンプトで変更を依頼します。たとえば「CSS を簡潔にして、セレクターの重複ではなく CSS 変数を使う」、「3 つ目の切り替えを追加せず、既存の設定パネルにライトモードを組み込む」、「両方の切り替えにキーボードショートカットを追加する」などです。

## 作業内容を確認する

変更をコミットする前に、エージェントが編集した内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストの更新が含まれることがあります。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタムエージェントが示したアクセシビリティのパターン（ARIA 属性、キーボード操作、セマンティック HTML、local storage による設定の保存など）が反映されていることを確認します。
4. 問題がなければ **Source Control** パネルで変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat の agent mode を使って進行中のセッションを監視し、各ファイルの編集を確認して承認または取り消し、コンテキストを保ったまま追加の作業を依頼しました。

このレッスンでは、次の操作を行いました。

- エージェントの作業をリアルタイムで監視しました。
- 個々のファイル編集を承認または取り消しました。
- 追加のプロンプトでセッションの進行中に指示を出しました。

次の[レッスン][next-lesson]では、アクセシビリティ機能をプルリクエストとして公開し、このラボでローカルのカスタムエージェントが作成した変更をレビューします。
